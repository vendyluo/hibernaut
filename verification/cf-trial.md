# cf local trial — 2026-10-01

Source: `main` commit `3831547` plus the Vite+ 1 / Effect 4 working-tree
changes. The trial ran in an isolated disposable copy; the source repository was
not modified by the trial. This record preserves the findings independently of
the temporary directory. The experiment is not a migration ready to merge.

## Versions and route

macOS arm64; Node 24.21.0; npm 11.19.0; cf 1.0.0-beta.10;
Wrangler delegate 4.145.0; Workers types 5.20261001.1.
The cf CLI delegates build/dev to Wrangler. The Cloudflare Vite bundler was not
tried. There was no login, remote API write, upload, or deployment.

## Findings

- cf migrate correctly converted the basic configuration, but required manual
  SQLite Durable Object lifecycle declarations. ChatAgent is now declared in
  worker.exports using exports.durableObject({ storage: "sqlite" }).
- Existing root workspaces ["test-workers"] block cf build/dev before execution:
  "application detection ... run in the root of a workspace".
- Adding "." to workspaces did not resolve this: cf reported multiple detected
  frameworks, "NPM + Hydrogen ., NPM + Hydrogen test-workers".
- For a diagnostic control only, the workspace declaration was removed from
  this copy. This unlocked cf project commands. It is not a proposed change to
  the original repository: the current trial lockfile still reflects the
  installed workspace graph, and clean installation of this layout was not
  validated. A complete adoption needs a supported application/workspace layout.
- String-valued Durable Object Worker references lose RPC/class types. Using
  defineWorker plus a typed entrypoint and a Worker config reference fixes the
  inferred ChatAgent namespace type without weakening the tests.
- A config edit during the running dev session ended that process with an
  uninformative [object Object] error. Root cause was not established. Restarting
  with the final config worked and the final smoke passed.

## Executed checks on the final trial configuration

- npm run typecheck: PASS, using .cloudflare/types generated by cf workers types
  --include-runtime=false and the new configs.
- npm test: PASS, 64 tests (33 Vite+ core; 31 Cloudflare pool/workerd).
  Workerd tests still read the preserved wrangler.jsonc; they do not independently
  verify the new cf config or remote Durable Object lifecycle.
- cf build: PASS, delegates to Wrangler.
- cf deploy --dry-run: PASS; 2832.16 KiB raw / 531.75 KiB gzip; ChatAgent binding
  recognized. No upload or deployment occurred.
- cf dev -- --ip 127.0.0.1 --port 8787 --persist-to .cloudflare/local-state plus
  npm run smoke: PASS on the final configuration, including echo, server state,
  rejected client overwrite and normal WebSocket close. The dev process stopped.

Conclusion: cf can run this Worker locally, but the current repository layout
cannot be switched directly. Workspace detection and dev-config reload behavior
need resolution before adoption. Original upgrade results remain in place.

## Minimal typed configuration used in the successful control

```ts
import { bindings, defineConfig, defineWorker, exports } from "cf/config";
import * as entrypoint from "./src/index.ts" with { type: "cf-worker" };

const worker = defineWorker({
  name: "hibernaut",
  compatibilityDate: "2026-08-01",
  compatibilityFlags: ["nodejs_compat"],
  entrypoint,
  exports: { ChatAgent: exports.durableObject({ storage: "sqlite" }) },
});

export default defineConfig({
  worker: {
    ...worker,
    env: {
      ChatAgent: bindings.durableObject({ worker, exportName: "ChatAgent" }),
    },
  },
});
```

This control also used `wrangler.config.ts` with
`defineWranglerConfig({ types: { generate: false } })`, generated types via
`cf workers types --include-runtime=false`, included `.cloudflare/types` and the
new configs in TypeScript, and enabled `allowImportingTsExtensions`.
These files were not applied to the repository. The lifecycle declaration was
validated locally only; it is not evidence that a deployed namespace or its
migration history can be switched safely.

The earlier forced pool 0.22.0 + Vitest 5.0.1 experiment failed workerd startup
with `SyntaxError: Unexpected identifier 'file'`. The newer renamed plugin was
not runtime-tested. Its published peer range does not establish Vitest 5 support.
Changing the development CLI to cf does not change the runner's declared support.
Keep the Workers suite on v4 and update the core runner together with the Vite+
toolchain rather than forcing a global Vitest override.

## Official migration status and next verification

The [cf announcement](https://blog.cloudflare.com/cloudflare-cf-cli-launch/)
states that cf is in open beta. A final Wrangler major is planned after beta,
with 18 months of maintenance after beta ends; Wrangler is not already removed
or unsupported. The [migration guide](https://developers.cloudflare.com/cf/wrangler/migrate/)
explains the config conversion, Durable Object follow-up, generated types and
local dry-run validation.

Before adopting cf, resolve root application/workspace detection while retaining
both test runners; validate a clean install and matching lockfile for that layout;
rerun typecheck, both suites, build, dry-run and local smoke; and investigate the
config-reload exit or establish its reproducibility. A Vite bundler conversion
and remote Durable Object lifecycle validation remain separate, untested work.
Do not infer release/deployment readiness from this local control experiment.
